HSD-Party

OVERVIEW & PREMISE

As part of the multiplayer party game "HSD-Party", I developed the complete 3D board game system. The gameplay principle is inspired by classic digital board games (such as Mario Party) and serves as the main playing stage for players to travel along and collect stars (or in this case Bachelor degrees).

As the developer of the board system, my focus was on the concept, architecture, and implementation of all core board logic mechanics:

  • Path & Graph Navigation: Networked movement across 3D tiles, including branching selectable paths (Split Tiles)

  • Round & Turn Management: Sequential turn control for up to 4 players, camera focusing, and round transitions with minigame triggers.

  • Dynamic Star System: Randomized placement of the primary goal (degree/stars) on the board with automatic path recalculation and camera presentation.

  • Item & Inventory System: Utilization of specialized dice, teleporters, stealing mechanics, and duel items.

  • Polymorphic Tile Architecture: Various interactive tile types such as quiz tiles (featuring campus questions), item shops, teleport points, event tiles, and negative/penalty tiles.

The primary goal for players is to collect the most stars (degrees) and coins over a fixed number of rounds through strategic movement and clever item usage.

TECHNICAL HIGHLIGHTS & ARCHITECTURE

The system architecture was developed to be modular, type-safe, and event-driven in Godot 4.5. It is structured into the following core technical components:

A) Path System & Board Topology (Graph & Linked List)

  • Doubly Linked Network: Board tiles (BiggameHSDCampus_Tile) are automatically read from the scene at runtime and linked as a connected graph (last_tile / next_tile).
  • Branching Paths (SplitTile & PathManager): When a player reaches a junction, the system pauses movement and activates an interactive direction selection. A visual 3D indicator (arrow sprite) previews the chosen route prior to confirmation.

B) State Machine & Player Movement

  • State-Based Player (BiggameHSDCampus_Player): Controlled via a Finite State Machine (FSM) featuring the states IDLE, MOVING, CHOOSING_ITEM, USING_ITEM, ON_SPLIT_TILE, FREE_CAM, and IN_MINIGAME.
  • Smooth Movement: Step-by-step movement along waypoints using Godot Tweens, combined with walking animations, sound effects when stepping on tiles, and remaining step management (rest_move).

C) Dynamic Star System (StarManager)

  • Rule-Based Generation: At round start or following a star purchase, the StarManager randomly selects an eligible board tile. Junctions, teleport spots, and the previous star spot are automatically filtered out.
  • Runtime Instantiation: 3D star models (BookR.glb) are dynamically instantiated with continuous rotation animations.
  • Cutscene Integration: An automated camera track presents the new star location on the board to all players.

D) Polymorphic Tile Hierarchy (BiggameHSDCampus_Tile)

All tiles inherit from a shared base class and extend gameplay polymorphically:

  • QuizTile: Displays a quiz UI, pauses board view, plays camera intro animations, and rewards/penalizes correct or incorrect answers with coins.
  • ShopTile & SpecialShopTile: Opens an interactive shop featuring a 3D vendor model, dynamically populated item inventory from a pool, and coin deduction.
  • TeleportTile: Executes a 3D elevator lift/lower animation and seamlessly transfers the player to the target teleporter, including camera angle adjustment.
  • EventTile & NegativeTile: Trigger dynamic events (coins +/- , steps forward/backward) with randomized values.

E) Item & Inventory System

(InventoryManager, ItemFactory, Resource-Items)

  • Data-Driven Items: Items are defined as Godot Resource instances (BiggameHSDCampus_Item), enabling easy extension within the editor.
  • Item Types:
    • Dice Modifiers: BIG_DICE (dice roll 8-10), SMALL_DICE (dice roll 1-4).
    • Interactive Magic / Abilities: STEAL_COINS (steals coins from a selected target player), STEAL_ITEM (steals a random item from a target's inventory), TELEPORT_TO_OTHER (teleports to a target player's tile), TELEPORT_TO_STAR (direct teleport to the active star), DUELL_ITEM (triggers direct duels).
  • Player Selection Process: Asynchronous target selection process for targeted items using player input signals.

F) Turn Manager & Camera System

  • Turn Control (TurnManager): Transfers control to the next player after a turn ends, smoothly fades UI elements and color codes (Fade In/Out), and checks match-ending conditions or transitions to the minigame phase at the end of a round.
  • Dynamic Camera (BiggameHSDCampus_CameraLogic): Supports automatic perspective switches depending on path sections, camera tracking during interactions, and a manual free-cam inspection mode for players.

3. Project Metrics & Tech Stack

  • Engine: Godot Engine 4.5 (Forward Plus Rendering Pipeline)
  • Programming Language: GDScript (Strict static typing with enabled compiler warnings for maximum code quality)
  • Architecture Patterns:
    • Finite State Machine (FSM)
    • Observer Pattern (Godot Signals)
    • Factory Pattern (ItemFactory)
    • Graph / Doubly-Linked List Topology
    • Resource-driven Architecture
  • Testing Framework: Integration of the GUT (Godot Unit Testing) plugin.
